Advanced: firmware data contract
Firmware data contract
JSON v1
USB: send one JSON object per line. HTTP: return the same object from /api/sensors every poll. Send calibrated readings; unavailable sensors may be null.
{"moisture":42,"ph":6.5,"temperature":28.4,
 "humidity":64,"nitrogen":120,"phosphorus":45,
 "potassium":80,"ec":1.2,"pumpOn":false}
Pump commands use an explicit desired state and unique ID. USB commands also include a token; HTTP sends it in the Authorization header:
{"type":"pump","id":"unique-command-id","on":true,"token":"your-control-token"}
After applying the output, firmware must acknowledge:
{"type":"ack","id":"unique-command-id","pumpOn":true}
USB: send the acknowledgement as a new line. HTTP: return it as the POST response. Commands time out after 5 seconds and are never retried automatically. “Pump on” is the controller’s reported state, not verified water flow.
Board wiring and sensor drivers depend on your exact hardware. This interface does not flash firmware or assume relay pins.
